# Expo and API deployment

The frontend supports installed iOS/Android apps plus an optional Expo static web export. The backend remains a supervised FastAPI process connected to PostgreSQL. Dependency setup uses uv/uv.lock. No deployment or signed build was performed by this migration.

## Native builds with EAS

From frontend/:

```sh
npx eas-cli@latest build --profile development --platform android
# Or --platform ios
npm start -- --dev-client
```

`eas.json` defines development (custom dev client, internal distribution), preview (internal build; Android APK), and production (auto-increment) profiles. Configure an EAS project/account and team-owned bundle IDs before distribution; current identifiers edu.campus.messaging are placeholders. Use `npx eas-cli@latest build --profile preview --platform android` for an internal installed Android build, or the corresponding iOS profile/platform with signing configured. Production submissions use `npx eas-cli@latest submit` after a successful signed build.

Set EXPO_PUBLIC_API_URL to an HTTPS API reachable by classmates/devices in the EAS build environment before building. Environment values are embedded into the JS bundle; changes require rebuilding or a configured OTA update. Native Cognito callbacks use campusmessaging://auth/callback, which must be registered in Cognito and backend COGNITO_APP_REDIRECT_URIS. A dev/installed build owns that scheme; Expo Go does not support this sign-in flow. Native source directories are generated by Expo and are not edited by hand.

## Web build and Nginx

From frontend/, set the deployed API URL in the build environment and run:

```sh
npm ci
EXPO_PUBLIC_API_URL=https://your-domain.example npm run build
```

Serve dist/ from the web root. `nginx.conf.example` serves `/var/www/campus-app/dist`, proxies `/api/` to 127.0.0.1:8000, disables buffering for SSE, and uses a one-hour proxy read timeout. Replace the hostname and add HTTPS. `proxy_pass` has no URI suffix, preserving the /api/ path.

The Expo web `/auth/callback` is a **frontend** code-exchange route; do not proxy it to the legacy FastAPI callback. The example tries `$uri.html` so the static exported auth/callback.html is served correctly. Web login returns to this route in the same tab and validates the saved PKCE transaction before establishing the application session. The new authentication flow uses `/api/auth/config`, `/api/auth/session`, and `/api/auth/logout`, all covered by the API proxy. Legacy cookie endpoints remain on the backend for old integrations but are not used by Expo.

Register https://your-domain.example/auth/callback in Cognito and COGNITO_APP_REDIRECT_URIS. Set FRONTEND_ORIGINS to the deployed browser origin (especially if API/web have different origins). The Expo client uses Authorization and omits cookies. For any legacy cookie consumers, set FRONTEND_URL and COOKIE_SECURE=true and expose their backend callback deliberately through a nonconflicting host/path.

## API runtime

```sh
cd backend
uv sync --locked --no-dev
uv run --locked --no-dev alembic upgrade head
uv run --locked --no-dev uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Review migrations against the existing schema before deployment. Run the service under a process supervisor with backend environment and database access configured. Keep one worker until shared sessions/event distribution are implemented. Restrict direct backend exposure as appropriate; native clients should reach a secured public API hostname through the proxy.

## Operational limits

Database persistence does not make auth/event state shared: API restarts invalidate sessions and multiworker routing can miss auth or live events. SSE has no durable replay IDs, and offline recovery can retrieve only latest-100 history. Queue overflow closes a stream to trigger reconnection; private streams close after session revocation/expiry checks. Public writes remain anonymous and lack rate limiting. There is no push/background notification service.

Verify full sign-in/logout, native callback handling, device API reachability, browser CORS, public/private delivery, and membership enforcement before team distribution. Backups, credentials, process supervision, monitoring, and migration rollout are not automated here. The tracked pre-DM dump was not inspected and is not assumed to be a current backup.
