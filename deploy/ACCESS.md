# CATS team access

Generated by OpenAI Codex on 2026-11-01.

## Website accounts

Open https://cats.tufts.pro and choose **Sign in with Cognito**, then **Sign up**.
Use a `cmich.edu` email address and complete the emailed verification code. The
pre-sign-up Lambda rejects other domains, and the API independently requires a
verified email from that exact domain. Subdomains and lookalikes are rejected.

The dedicated CATS pool is separate from the messaging demo's pool. Existing demo
accounts are not automatically copied; create a CATS account. There is no shared
client secret. OAuth uses authorization code + PKCE, state, nonce, JWT signature,
issuer/client/type/expiry validation, and a browser-binding cookie. The browser
receives only an opaque Secure/HttpOnly/SameSite=Lax session cookie. Sessions expire
after at most 15 minutes; sign in again to renew. Logout deletes the DB session.

This is web authentication. Native mobile authentication is not yet implemented;
local Expo development remains available with its isolated development database.
Do not point native development at production and disable authentication to work
around it. AUTH_REQUIRED=0 is for the localhost development stack only.

## Administrator operations

Public keys belong in root-owned `/etc/ssh/cats-keys/cats-NAME` (mode 644), not in the
runtime user's home. Use an individually attributable key for each person. Revoke
by removing that person's key file and terminating their active sessions if needed.
Audit SSH authentication in the system journal and deployments under `cats-deploy`.

The runtime account remains catsdeploy, with no SSH keys or sudo rights. Its entire
home is an 8 GiB filesystem, mounted nodev/nosuid, and its user manager requires the
mount. RAM/CPU/process and network restrictions remain enforced. The original home
is retained root-only under `/var/lib/cats-storage/original-home` for migration
rollback; remove it only after a deliberate backup/rollback review. Image retention
is administrator-managed; a full CATS filesystem causes CATS uploads to fail rather
than filling the host filesystem.

Backups run daily at 07:00 UTC plus up to ten minutes of jitter and before deployments.
They go to `cats-backups-705154148633-us-east-2/daily/`. Public access is blocked,
SSE-S3 encryption and versioning are enabled, and objects have seven-day governance
retention. Current objects expire after 30 days; noncurrent versions after 90 days.
The EC2 role can PUT only to this prefix, not read/delete/bypass retention. Restore
requires an administrator identity with read access. A maximum of three bounded local
copies is retained. Check `systemctl status cats-backup.service` and the S3 newest
object timestamp; no external failure-notification destination is configured.

Restore into a NEW database first using pg_restore --exit-on-error, verify data and
PostGIS, then plan any production switch. Do not restore over the live database
without an explicit recovery plan. An S3 download/restore was successfully tested.

Nginx serves HTTPS, rate-limits authentication/API traffic, omits callback query
strings from access logs, and renews the certificate through Certbot. Existing sites
are unaffected. The API remains private on localhost:18082; PostgreSQL has no host
port. PostgreSQL 18 is the database major version; PostGIS is its spatial extension.

Remaining application limitations: messages are ephemeral and shared among signed-in
CMICH users; this does not add persistent conversations, private-message authorization,
or scheduling business rules. All CMICH users currently have the same app access.
